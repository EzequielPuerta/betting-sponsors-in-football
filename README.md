# betting-sponsors-in-football

Data stories about betting-company sponsors on football shirts. The first piece, **La camiseta no se mancha** (working title), is an interactive scrollytelling article built with SvelteKit.

The project is not tied to one country or season: the first story uses the Argentine Liga Profesional, and more leagues, seasons and stories will be added over time.

## First story: Argentine Liga Profesional

Readers pick six matches from the 240 played in the first phase of the tournament, then see how many featured betting sponsors on the shirts. The story then zooms out to the whole season:

- A per-match **betting impact index**: 0 if neither team has a betting sponsor, 0.5 if one does, 1 if both do.
- The index by round, and the season average.
- The ten clubs with a betting sponsor, and the zone of the shirt where each one appears.
- The industries behind every club's main sponsor.

Shirt photos mostly show the front, so only the visible zones (chest, upper chest, collar, sleeve and lower part) are analysed.

## Stack

- [SvelteKit](https://svelte.dev/docs/kit) 2 and Svelte 5 (runes), TypeScript
- Tailwind CSS 4 and daisyUI 5 (custom `journal-dark` / `journal-light` themes)
- [`@fundar/data-scrolly-telling`](https://www.npmjs.com/package/@fundar/data-scrolly-telling) and [`@fundar/data-chart-telling`](https://www.npmjs.com/package/@fundar/data-chart-telling) for the scrollytelling and the charts
- Python 3 (standard library only) to build the static data

## Data

The page loads static files from `static/data`, `static/crests` and `static/kits`. They are generated by `scripts/build_data.py`:

```sh
DATA_DIR=/path/to/football-kits python3 scripts/build_data.py            # uses the cached feed in scripts/raw
DATA_DIR=/path/to/football-kits python3 scripts/build_data.py --refresh  # downloads the fixture again
```

Outputs:

| File                          | Content                                                                   |
| ----------------------------- | ------------------------------------------------------------------------- |
| `static/data/matches.json`    | Matches with round, date, kick-off time, venue, score and betting impact  |
| `static/data/teams.json`      | Teams with crest, kit and detected sponsors (and which ones are betting)  |
| `static/data/sponsors.csv`    | One row per team and sponsor: industry, shirt zone, main sponsor, betting |
| `static/data/industries.json` | Main sponsor of each club grouped by industry, ready for the wheel chart  |

Sources:

- **Matches, results, kick-off times and venues:** the public Opta feed that powers the fixture widget on [ligaprofesional.ar](https://www.ligaprofesional.ar/).
- **Kits and sponsors:** the `football-kits` project, which detects logos on kit images (OCR plus a logo detector), reviewed by hand. `DATA_DIR` must point to its processed CSVs and images.

Kits are matched per team using the 2026 home shirt, so each team's sponsors are the same in all its matches. This is an approximation: a team may play in a different shirt.

## Project structure

```
src/
  lib/
    components/   shared components (hero, footer, scrolly wrappers, tooltips)
    constants/    shared constants (colors, chart settings, impact levels)
    registry/     static data files and how they are parsed
    stores/       data loading, picks, device
    types/        shared types
    utils/        pure helpers (impact stats, formatting, point positions)
  routes/
    sections/     one folder per section of the story
      pick/       scrollytelling where the reader picks six matches
      result/     the reader's result
      impact/     scrollytelling with the full-season analysis
scripts/          data pipeline
static/           generated data, crests and kits
```

Each section has its main component (`Main.svelte` or the section's own file) and a `components/` folder with the pieces only it uses. The `$lib` and `$sections` aliases point to `src/lib` and `src/routes/sections`.
